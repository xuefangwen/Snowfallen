# 更新源码与安装包

Git 是本地版本记录工具；commit 是一次有说明的版本快照；push 是把本地提交发送到 GitHub。GitHub Desktop 的 Changes 显示待提交差异，History 显示已保存历史。

1. 从实际开发工程同步明确需要的源码和本地化；保留 JSON 标识符、动态占位符和手改文字。
2. Beta 与正式版分别维护和编译。不要把其中一版构建成功当成两版都通过。
3. 审查 Changes 的文件名和内容，排除任何缓存、图片原稿、日志、备份、探针、游戏/第三方 DLL 及个人文件，再 commit 和 push。
4. 完整安装包分别核对 DLL/PCK/清单及内嵌资源，更新许可、安装说明、哈希和实际验证边界。
5. 完整 ZIP 作为 Releases 附件发布，不提交进 Git；自动生成的 Source code ZIP 不能作为安装包。

`.gitignore` 只帮助忽略未跟踪文件，不会清除已提交文件或旧历史。合并其他工程的 Git 历史前也应审查其中的文件，避免带入无关内容。

Git LFS 用于大型二进制文件的单独管理；本源码仓库只有小型文本，不需要启用。两份安装包在 Releases 分别下载，只安装匹配分支的一份。

本仓库是独立发布副本，不会自动同步其他工程或对话的后续修改。每次发布前应重新核对实际来源，不能按旧哈希或目录日期认定最新。
